## Design

One flat `Claudio.Admin` module (not 6 sub-modules) with a shared private request helper — DRY, discoverable, mirrors the thin-wrapper style of `Claudio.Models` / `Claudio.Files` (return raw decoded body `{:ok, map()}`; non-2xx → `Claudio.APIError`; transport error → `{:error, term()}`):

```elixir
defp get(client, url, params \\ []), do: handle(Req.get(client, url: url, params: params))
defp post(client, url, body),        do: handle(Req.post(client, url: url, json: body))
defp delete(client, url),            do: handle(Req.delete(client, url: url))
defp handle({:ok, %Req.Response{status: s, body: b}}) when s in 200..299, do: {:ok, b}
defp handle({:ok, %Req.Response{status: s, body: b}}), do: {:error, APIError.from_response(s, b)}
defp handle({:error, reason}), do: {:error, reason}
```

Query params: list endpoints pass their keyword opts straight through as `params:` (Req encodes), so callers control pagination/filters without per-key plumbing.
