## Verified facts (admin-api / authentication docs, 2026-06-19)

- The API accepts **either** `x-api-key: <key>` **or** `authorization: Bearer <token>`.
- Bearer is used for Workload Identity Federation (`org:admin` OAuth tokens, obtained via `POST /v1/oauth/token`) and Claude-Code-style tokens (which additionally need `anthropic-beta: oauth-2025-04-20`).
- `Claudio.Client` currently hardcodes `{"x-api-key", token}` in `get_headers/1`.

## Design (backward-compatible)

Add an optional `:auth_type` field to the `new/2` config map:

- `:api_key` (**default**, or omitted) → `{"x-api-key", token}` — unchanged from today.
- `:bearer` → `{"authorization", "Bearer #{token}"}` and **no** `x-api-key`.

The `:token` field carries the credential in both modes. Header **order is preserved** (auth header stays last of the base three, beta still prepended) so existing header assertions don't shift.

```elixir
defp auth_header(%{auth_type: :bearer}, token), do: {"authorization", "Bearer #{token}"}
defp auth_header(_auth, token), do: {"x-api-key", token}
```

OAuth token *exchange* (`POST /v1/oauth/token`) and Bedrock/Vertex transports are **not** built here — documented as future work. For Claude-Code OAuth tokens, callers pass `beta: ["oauth-2025-04-20"]`.
