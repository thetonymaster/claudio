# S14 — Tool extensions (tool search, programmatic calling, advisor, client toolsets, server-result typing)

- **Date:** 2026-09-26
- **Spec status:** Design approved by Q in chat (2026-09-26); written spec awaiting Q's review.
- **Scope class:** request helpers + `add_tool/3` options + response typing/round-trip fixes + new
  `Response.container` + `Tools` additions + `Claudio.Agent` loop changes. Ships in **0.7.0**
  (single bump after S15).
- **Scope decision (Q, 2026-09-26):** one S14 spec (not split into S14a/S14b); includes
  `browser_toolset_20260801` (same mechanics as the computer toolset).
- **Provenance:** live docs fetched 2026-09-26 under `platform.claude.com/docs/en/` —
  `agents-and-tools/tool-use/tool-reference` (TR), `…/tool-search-tool` (TS),
  `…/programmatic-tool-calling` (PTC), `…/advisor-tool` (ADV), `…/computer-use-tool` (CU),
  `…/browser-use-tool` (BU), `…/code-execution-tool` (CX), `api/messages/create` (REF),
  `release-notes/overview` (RN) — plus live probes T1–T4 (2026-09-26, `claude-opus-5-5` unless
  noted).

## Problem

Opus 5.5 accepts only `computer_toolset_20260801` for computer use, and Claudio can neither
declare it nor replay it: `Response.block_to_api/1` rebuilds `tool_use` as
`type/id/name/input`, dropping `toolset_name`, so the next request is a 400 (T1d). Programmatic
tool calling needs the response's `container` on the continuation (400 otherwise, T3c), and
`Response` has no `container` field. Tool search, `defer_loading`, `allowed_callers` and the
advisor tool have no helpers; the advisor's replay needs a beta nothing declares (T4b). Server-tool
result blocks other than `web_search_tool_result` are untyped, with no reader. `Claudio.Agent`
dispatches by name only, never echoes `toolset_name`, never carries the container, and treats
`pause_turn` as final.

## Design

### 1. Request helpers

- **`add_tool/3`** (`add_tool/2` unchanged, delegates with `[]`):
  - `defer_loading: boolean` → `"defer_loading"`.
  - `allowed_callers: [:direct | :code_execution | String.t()]` → `:direct` ↦ `"direct"`,
    `:code_execution` ↦ `"code_execution_20260120"` (the value responses report, F3), strings
    as-is.
  - `ArgumentError` for an unknown option, a non-boolean `defer_loading`, a non-list
    `allowed_callers`, or an atom other than `:direct`/`:code_execution`.
  - F2/F6 rules are left to the API.
- **`add_tool_search_tool(req, :regex | :bm25)`** → the F1 map. Other values raise.
- **`add_advisor_tool(req, model, opts)`** → `%{"type" => "advisor_20260301", "name" => "advisor",
  "model" => model}` plus `max_uses`, `max_tokens`, and `caching: "5m" | "1h"` ↦
  `%{"type" => "ephemeral", "ttl" => ttl}` when given; declares `advisor-tool-2026-03-01`.
  Unknown options / other `caching` values raise. Executor/advisor pairing is left to the API.
- **`add_computer_toolset(req, opts)`** / **`add_browser_toolset(req, opts)`** →
  `%{"type" => "computer_toolset_20260801"}` / `"browser_toolset_20260801"` plus
  `configs: %{member => %{enabled: bool, defer_loading: bool}}` (member and field keys
  stringified; atom or string input) and `cache_control: map` when given. No beta. Member names
  and F9 rules are left to the API; unknown option keys raise.
- **`add_computer_tool/4`** gains `version: :"20251124"` → `computer_20251124` + beta
  `computer-use-2025-11-24`; default stays `computer_20250124` + `computer-use-2025-01-24`.
  Other versions raise. Its doc points Opus 5.5 users to `add_computer_toolset/2` (F14).
- **Replay beta in `add_message/3`:** declares `advisor-tool-2026-03-01` when list content holds
  an `advisor_tool_result` block, or a `server_tool_use` whose name is `"advisor"` (string or
  atom keys, raw or typed) (F8).

### 2. `Claudio.Tools`

- `extract_tool_uses/1` returns `%{id, name, input, toolset_name, caller}` (`nil` when absent;
  the S12b `since_last_fallback` filtering is kept).
- `create_tool_result/4` — `create_tool_result(id, result, is_error \\ false, opts \\ [])`;
  `toolset_name: String.t()` adds `"toolset_name"`. Unknown options raise.
- `halt_result(tool_use) :: tool_result()` — for a tool use with `toolset_name` `"computer"` or
  `"browser"`: `is_error: true`, `toolset_name` echoed, content the exact F12 text. Any other
  input raises `ArgumentError` (the halt contract exists only for toolsets).
  `halt_text(toolset_name) :: String.t() | nil` exposes the text (nil for other toolsets).

### 3. Response parsing and round-trip

- `tool_use` gains `caller` and `toolset_name`; `server_tool_use` gains `caller` (`nil` when
  absent). `block_to_api/1` still rebuilds these maps (not `raw`: a streamed `tool_use` carries
  an undecoded `partial_json` key, F18) and adds `"caller"` / `"toolset_name"` when non-nil —
  fixes F10's T1d failure.
- Shallow typing (Q, 2026-09-26) for `web_fetch_tool_result`, `code_execution_tool_result`,
  `bash_code_execution_tool_result`, `text_editor_code_execution_tool_result`,
  `tool_search_tool_result`, `advisor_tool_result`:
  `%{type: <atom>, tool_use_id: String.t(), content: term(), caller: map() | nil, raw: map()}`;
  `content` stays the raw nested value. `container_upload` → `%{type: :container_upload,
  file_id: String.t(), raw: map()}`. `block_to_api/1` returns `raw` for all of them (they arrive
  whole, F16).
- `web_search_tool_result` keeps `tool_use_id`/`content`, gains `caller` and `raw`, and its
  `block_to_api/1` returns `raw` — so a `caller` on it now round-trips.
- `get_server_tool_results/1` — every block of the seven result types above plus
  `web_search_tool_result`, in content order; `get_server_tool_results/2` filters by type atom.
- New struct field `container :: map() | nil` — raw top-level `container`.
- `to_assistant_content/1`'s fallback pairing rule already matches any block's `tool_use_id`, so
  the new result blocks pair correctly with no change.

### 4. Streaming

`build_final_message/1` keeps `message_start.message.container` (it already stores the message)
and overwrites it with a non-nil `message_delta.delta.container` (F5). Result blocks need no code
(F16).

### 5. `Claudio.Agent`

- **Handlers:** `%{name => (input -> result)}` as today, plus toolset handlers keyed by
  `toolset_name`: `%{"computer" => (member, input -> result)}`. `result` is
  `{:ok, String.t() | [map()]} | {:error, String.t()}` (a list carries e.g. an `image` block for
  `screenshot`); `@type handler` is widened accordingly.
- **Dispatch (pair rule, F11; Q, 2026-09-26):** a `tool_use` with `toolset_name` goes **only** to
  `handlers[toolset_name]` as arity 2; without it, to `handlers[name]` as arity 1. Missing
  handler → error result ("Unknown tool: …" / "Unknown toolset: …"); wrong arity → error
  result ("Handler for … must take (input)" / "(member, input)"); raises,
  throws and exits → error result as today. Toolset results echo `toolset_name`.
- **Batch halt (F12):** a turn's calls run in content order. After the first failed call of a
  toolset **with a halt contract** (`Tools.halt_text/1` non-nil: computer, browser), that
  toolset's later calls in the turn are not executed; each gets `Tools.halt_result/1`. Other tools and the other toolset keep running. `on_tool_call` is not
  invoked for skipped calls.
- **Programmatic calls** dispatch the same way (their `caller` is ignored for dispatch); the
  follow-up user turn already holds only `tool_result` blocks (F6).
- **Container:** when a response has `container`, the next request gets its id (F5): a map
  container the caller set (e.g. `%{"skills" => …}`) keeps its keys and gains `"id"`;
  otherwise `set_container(req, id)`. (Plan review, 2026-09-26: a bare id would drop skills.)
- **`pause_turn`:** append the assistant content and call again (no user message); counts as a
  turn toward `max_turns`, so endless pausing ends in `:max_turns_exceeded`.
- Return shapes, `max_turns` counting, and `on_tool_call`'s signature are unchanged.
  `run/4`'s doc is corrected (Q, 2026-09-26): `max_turns` caps **model calls** (verified:
  `max_turns: N` → N calls); it previously claimed N+1 calls.

### 6. `count_tokens` and Batches

No change (F17). Batches get betas via `required_betas/1` already.

## Testing

- **Unit (`request_test.exs`):** `add_tool/3` each option, mapping of `:direct`/`:code_execution`,
  raises; `add_tool/2` unchanged; `add_tool_search_tool/2` both variants + raise;
  `add_advisor_tool/3` minimal/all options, beta, raises; both toolset helpers with `configs`
  (atom and string keys) and `cache_control`, no beta, raise on unknown option;
  `add_computer_tool/4` default and `version: :"20251124"` (type + beta), raise; `add_message/3`
  advisor beta for a typed and a raw advisor block, none otherwise.
- **Unit (`tools_test.exs`):** `extract_tool_uses/1` exposes `toolset_name`/`caller` (nil when
  absent); `create_tool_result/4` with `toolset_name`; `halt_result/1` exact texts for both
  toolsets, raise for a plain tool use.
- **Unit (`response_test.exs`):** `tool_use` with `caller` + `toolset_name` parses and
  `to_assistant_content/1` re-emits both (the T1d regression); without them, output is
  byte-identical to today; `server_tool_use` `caller`; each result type parses shallowly (string
  and atom keys) and replays `raw`; `web_search_tool_result` keeps its fields and gains
  `caller`/`raw`; `get_server_tool_results/1,2`; `container` present/absent.
- **Unit (`messages/stream_test.exs`):** container from `message_start`, overwritten by a non-nil
  `message_delta.delta.container`, kept when the delta has `null`.
- **Unit (`agent_test.exs`, Bypass):** pair dispatch with a custom `screenshot` tool beside the
  computer toolset (each handler gets only its calls); toolset result echoes `toolset_name`;
  missing toolset handler → error result; batch halt (fail on 2nd of 4 computer calls → 3rd/4th
  get the halt text, a plain tool in the same turn still runs); container carried to the next
  request body; `pause_turn` resumes with the assistant content and no user message; endless
  `pause_turn` stops at `max_turns`.
- **Integration (`test/integration/tool_extensions_integration_test.exs`)**, small prompts:
  1. Computer toolset screenshot → `Tools.create_tool_result/4` with `toolset_name` → 200 (T1c).
  2. Tool search + deferred tool → reply → 200 (T2b).
  3. Programmatic call → continuation with `container` → 200 (T3d).
  4. Advisor (executor `claude-sonnet-5`, advisor `claude-opus-5-5`) → replay without the tool
     in `tools`, beta auto-declared by `add_message/3` → 200 (T4c).
  5. `Agent.run/4` over 1 and 3 end to end (toolset handler; programmatic handler) → `{:ok, _, _}`.

## Out of scope

- Newer `web_fetch_20260309`/`20260318` and `web_search_20260318` options (`use_cache`,
  `response_inclusion`) — separate follow-up.
- Deep typing of nested result variants (Q, 2026-09-26: shallow only).
- Local validation of member names, `configs` rules, PTC incompatibilities, advisor pairing,
  result content types.
- Decoding streamed `partial_json` into `input` (pre-existing limitation, tracked since S12b).
- Client-side custom tool search (`tool_reference` inside a `tool_result`) helpers — works with
  raw content today.
